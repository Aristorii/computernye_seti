**1. HTTP (расшифруй и объясни назначение)**

HTTP — HyperText Transfer Protocol (протокол передачи гипертекста)

Это прикладной протокол передачи данных, лежащий в основе работы Всемирной паутины. Он определяет, как клиент (например, браузер) и сервер обмениваются сообщениями: клиент отправляет запрос, сервер возвращает ответ. HTTP описывает формат этих сообщений (стартовая строка, заголовки, тело), методы (GET, POST, PUT, DELETE и др.) и статус-коды (200, 404, 500 и т.д.). HTTP работает поверх TCP (а в современных версиях — поверх QUIC/TCP с TLS).

**2. HTTPS — чем отличается от HTTP?**

* HTTP — это как открытка: все, кто её видит по пути, могут прочитать, что ты написал

* HTTPS — это та же открытка, но в запечатанном конверте: прочитать может только получатель

Три главных отличия:

* Шифрование. В HTTP данные идут открытым текстом — пароли, сообщения, куки может перехватить любой по пути (в кафе, у провайдера). В HTTPS всё шифруется, перехватчик увидит только «мусор»

* Проверка сервера. HTTPS гарантирует, что ты общаешься именно с тем сайтом, кем он представился (через сертификат). В HTTP легко подменить сайт на фейковый
  
* Порт. HTTP по умолчанию — порт 80, HTTPS — порт 443

**3. Клиент-серверная модель — что это?**

Это архитектурная модель взаимодействия, при которой:

* Клиент — инициатор запросов (браузер, мобильное приложение, скрипт). Он отправляет запросы и обрабатывает ответы

* Сервер — пассивная сторона: принимает запросы, обрабатывает их, хранит данные и возвращает ответы

Клиент и сервер общаются по сети по определённому протоколу (например, HTTP)

Ключевые свойства: разделение ответственности, сервер обслуживает множество клиентов одновременно, клиент не знает внутреннего устройства сервера (и наоборот)

**4. Идемпотентность — что означает?**

Идемпотентность — свойство операции, при котором её многократное выполнение даёт тот же результат (состояние сервера), что и однократное

В HTTP:

* Идемпотентны: GET, HEAD, PUT, DELETE, OPTIONS, TRACE.

* Не идемпотентны: POST, PATCH (в общем случае).

1. **Метод** — POST

2. **Путь (endpoint)** — /api/users

3. **Версия HTTP** — HTTP/1.1

4. **Content-Type** — сообщает серверу, что тело запроса имеет формат JSON (application/json), чтобы сервер правильно его распарсил

5. **Authorization** — заголовок аутентификации; здесь используется схема Bearer с JWT-токеном, который удостоверяет личность клиента и его права

6. **Тело запроса***— после пустой строки: {"name": "Иван", "email": "ivan@mail.com"} (его длина 58 байт соответствует Content-Length)

1. **201 Created** — статус-код «Создано»: запрос успешно выполнен, и в результате на сервере создан новый ресурс

3. **В теле ответа** — JSON-представление созданного пользователя: {"id": 42, "name": "Иван", "email": "ivan@mail.com"}
